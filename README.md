# Project 03: Flow Matching

In this project you implement flow matching in PyTorch and train it on the same data as in Projects 01 and 02, a small subset of MNIST: the digits 0, 1, 2, 3, 4 as gray images of 32 x 32 pixels, without labels.

| Data | Images | File |
|---|---|---|
| training | 100 per digit (500 in total) | `data/mnist_train.pt` |
| testing | 1000 per digit (5000 in total) | `data/mnist_test.pt` |

The method has two parts:

- **Training**: you train a velocity field `v(x, t)` on the images. It moves noise `x ~ N(0, I)` at `t = 0` to the training images at `t = 1`, and it is trained by flow matching with straight paths from noise to data.
- **Sampling**: a new image is generated by drawing noise and moving it from `t = 0` to `t = 1` along the velocity field with the Euler method.

Your trained model is measured on the test images by one value. Lower is better.

- **FID** (Frechet inception distance) between 5,000 images generated by your model and the 5,000 test images.

## 2. Set up the Python environment

Run these commands in the `project-03` folder. They create a virtual environment in the folder `.venv`, activate it, and install the packages.

macOS and Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Windows (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Activate the environment again every time you open a new terminal (the second command).

Notes:

- The installation downloads PyTorch, which is large; it can take several minutes.
- On Windows, pip installs a CPU-only build of PyTorch. To use an NVIDIA GPU, first install `torch` and `torchvision` with the command given at <https://pytorch.org/get-started/locally/>, then run the last command above.
- The notebook uses an NVIDIA GPU (`cuda`) or the GPU of an Apple silicon Mac (`mps`) when there is one, and the CPU otherwise.

## 4. Do the assignment

Write the five files of the `code` folder. Every part to write is marked with `TODO`, and the docstring of each function specifies its inputs and outputs.

| File | What you write |
|---|---|
| `code/myinfo.py` | your name and student ID |
| `code/mymodel.py` | the velocity field |
| `code/myoptim.py` | batch size, number of epochs, optimizer |
| `code/mytrain.py` | path from noise to data, loss function, training for one epoch |
| `code/mysample.py` | number of steps, Euler method, generation of new images |

Rules:

- Keep the interfaces (names, inputs and outputs of the functions) unchanged: the notebook relies on them.
- Do not modify `assignment_03.ipynb`, the files in `util`, or the files in `data`.
- Train with the training images only. The test images are for the evaluation at the end of the notebook.
- The path from noise to data, the loss function and the Euler method are the ones specified in `code/mytrain.py` and `code/mysample.py`: the notebook checks their values.
- The architecture of the velocity field, the optimizer and its settings, the batch size, the number of epochs and the number of steps of the Euler method are your choices: try to make the FID as low as you can.

Then run the notebook from top to bottom with *Restart* and *Run All*. It stops with an error message at the first part that is not written yet or does not have the expected interface. When it runs to the end, it has saved:

| File | Content |
|---|---|
| `train/loss.png` | training curve |
| `train/model.pt` | trained velocity field |
| `sample/sample.png` | images generated by the trained model |
| `result/trajectory.png` | images along the paths from noise to data |
| `result/steps.png` | images generated with different numbers of steps |
| `result/result_<student ID>_<name>.csv` | FID |

About the training:

- The loss of flow matching does not go down to 0: a point of a path can be reached from many pairs of noise and data, which do not have the same target velocity.
- The loss also changes from one epoch to the next, because the noise and the times are drawn at random: look at the generated images of `sample/sample.png` as well.

About the last section of the notebook (results):

- The first run downloads the network used by the FID (about 100 MB), so it needs an internet connection.
- It takes seconds with a GPU, but can take more than 10 minutes with a CPU.
